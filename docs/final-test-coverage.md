## 4. العيب الوحيد المكتشف: الاختبار النهائي للدرس الأول كان غير قابل للوصول

**العرض:** `Lesson1.tsx:950` يركّب `<FinalQuiz lesson={1} accent="bg-slate-900" />` داخل فرع
`case "quiz":`، وبنك `QUIZZES[1]` موجود (12 سؤالًا بمفاتيح وشرح)، لكن **قائمة `SLIDES` في
`lesson1/data.ts` لم تحتوِ أي شريحة `kind: "quiz"`** — ظهر `kind: "quiz"` مرة واحدة فقط في
الملف كله، داخل اتحاد الأنواع (`data.ts:55`) لا في القائمة. النتيجة: الفرع الذي يرندر
الاختبار لا يُستدعى أبدًا، والطالب لا يصل إلى اختبار الدرس الأول إطلاقًا.

**الإثبات (قبل الإصلاح):** المشي الفعلي للدرس قطع 20 خطوة (كل شرائح الدرس) دون أن يظهر إقليم
الاختبار النهائي مرة واحدة؛ وأكّد الفحص البنيوي أن عدد شرائح `quiz` = 0 بينما بقية الدروس
(2–26) تملك شريحة واحدة.

**نقطة الاختفاء:** تاريخ المستودع المتاح يبدأ من الجذر `4dcedb5` (عمق التاريخ = 2 فقط:
`4dcedb5` ثم `4f31a91`)، والشريحة غائبة منذ ذلك الجذر. أي أن الحذف أقدم من التاريخ المتاح،
ولا يمكن نسبته إلى التزام محدد داخل هذا المستودع.

**الإصلاح (سطر واحد في البيانات — لا إعادة بناء):** أُضيفت الشريحة المفقودة بنفس اصطلاح بقية
الدروس (مطابق لـ`lesson6/data.ts:477` و`lesson26/data.ts:1827`) وفي الموضع نفسه (آخر شريحة
محتوى قبل الختام):

```ts
{ kind: "quiz", section: END, mascot: "📝", title: "الاختبار النهائي" },
```

لم يُضف أي سؤال جديد، ولم يُنسخ أي اختبار: المكوّن المشترك `FinalQuiz` والبنك `QUIZZES[1]`
والفرع `case "quiz"` كلها بقيت كما هي — أُعيد وصلها فقط. عدد خطوات الدرس يُشتق من
`SLIDES.length` (`Lesson1.tsx:1034`) فلم ينكسر أي عدّاد.

**بعد الإصلاح:** الاختبار يظهر في الخطوة 20 من 21 (قبل شريحة الختام)، 12 سؤالًا، لا تسريب قبل
التصحيح، التصحيح يكشف النتيجة و12/12 شرحًا، إعادة الضبط تمسح كل شيء، ومفتاح المعلم يفتح
بـ`somer173` ويعرض 12/12.

## 7. حالة TypeScript — `TS5058`

**السبب الدقيق:** المستودع **لا يحتوي أي ملف إعداد TypeScript** إطلاقًا:

```bash
$ find . -name "tsconfig*" -not -path "./node_modules/*"   # لا شيء
$ git ls-files | grep -iE "tsconfig"                        # لا شيء
$ npx tsc --noEmit -p tsconfig.json
error TS5058: The specified path does not exist: 'tsconfig.json'.
```

ولا يوجد أمر فحص أنواع في المشروع: `package.json` فيه `dev`/`build`/`preview` (= `vite` فقط)،
وسير العمل `.github/workflows/pages.yml` يشغّل `npm ci` ثم `npm run build` فقط. أي أن
`vite build` (عبر esbuild) **يزيل الأنواع دون فحصها**، ونجاح البناء لا يعني سلامة الأنواع.
`typescript@5.9.3` مثبّتة كـ`devDependency` و`node_modules/.bin/tsc` موجود — فالأداة متاحة،
والناقص هو الإعداد لا البيئة.

**الاصطلاح المعتمد في هذا المستودع** (موثّق سابقًا في `docs/lesson29-coverage.md:106`
و`docs/lesson32-coverage.md:156`) هو تشغيل `tsc` مستقلًّا بأعلام صريحة على الوحدات المعنية،
وهو ما نُفِّذ هنا **دون كتابة أي ملف إعداد**:

