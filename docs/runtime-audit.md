# Fix #3 — التدقيق الشامل لوقت التشغيل في المتصفح لكل الدروس (Runtime / Browser Audit)

> **النطاق:** تدقيق فقط. لا يغيّر هذا العمل أي محتوى تعليمي، ولا أي مكوّن درس،
> ولا أي سؤال أو إجابة، ولا التوجيه (router)، ولا يبدأ «التحميل الكسول» (Fix #4).

## 1. ما يفعله التدقيق

يفتح **كل درس من 1 إلى 62** عبر مساره الحقيقي في تطبيق الإنتاج المبني
(`dist/`) في **Chromium حقيقي** (headless، عبر `playwright-core` مع
`@sparticuz/chromium` — نفس البنية الموجودة في تدقيقات المتصفح القائمة)، على
مقاسين: **سطح المكتب 1440×900** و**الجوال 375×812**.

لكل درس ولكل مقاس يتحقق من:

| # | الفحص |
| --- | --- |
| 1 | المسار `#/lesson/N` يُحمَّل ويُرسم محتواه فعلًا |
| 2 | الصفحة ليست فارغة (`body` نص ≥ 80 محرف) |
| 3 | محتوى الدرس مرئي ومعبّر (نص منطقة المحتوى ≥ 40 محرف) |
| 4 | عناصر تفاعلية/روابط مرئية موجودة |
| 5 | الهيكل العام `.site-gate-shell` موجود |
| 6 | زر «قفل الموقع» موجود ومرئي، وداخل عرض الشاشة أفقيًا، وقابل للوصول (بالتمرير إن لزم) |
| 7 | عنصر `<main>` موجود (منطقة محتوى الدرس) |
| 8 | لا فائض أفقي على المستند (≤ 1px) مع تشخيص أكبر العناصر المتسببة |
| 9 | المحتوى غير مقصوص بشكل خفي (`overflow:hidden` لا يخفي محتوى) |
| 10 | اتجاه الصفحة وجذر الدرس RTL |
| 11 | كل عوازل الإنجليزية (`.font-en`, `.ltr`, `[dir="ltr"]`) اتجاهها LTR فعليًا |
| 12 | لا أخطاء `console` غير متوقعة |
| 13 | لا أخطاء صفحة غير معالجة (`pageerror`) |
| 14 | لا طلبات شبكة تطبيقية فاشلة (`requestfailed`) |

ثم يتحقق من **التنقل الحقيقي** ومن **احتواء الانهيار** في القسم التالي.

## 2. تغطية التنقل والتعافي

| السناريو | التفصيل |
| --- | --- |
| الفهرس → درس | نقرة على بطاقة درس حقيقية في الفهرس (`a[href="#/lesson/7"]`) تفتح الدرس 7 بمحتواه |
| الدرس → الفهرس | زر العودة الفعلي. على سطح المكتب يظهر مباشرة في الشريط الجانبي (`direct`)، وعلى الجوال يُفتح عبر زر ☰ «فهرس» (`drawer`) — كلاهما مسار مستخدم حقيقي، ويُسجَّل أي مسار استُخدم |
| درس → الدرس التالي | تمشيط الدرس بالنقر على «التالي» حتى نهايته، ثم النقر على رابط «الدرس التالي» الحقيقي |
| درس → الدرس السابق | نفس الطريقة مع رابط «الدرس السابق» الحقيقي |
| «التالي» داخل الدرس | يغيّر محتوى الدرس فعلًا (سلوك الهيكل المشترك) |
| قفل الموقع | زر «قفل الموقع» يعيد بوابة كلمة المرور (`#site-password`) |
| احتواء الانهيار | انهيار مقصود لدرس واحد يُعرض بواجهة التعافي داخل حدّ الأخطاء (PR #117) لا صفحة بيضاء، ويبقى الهيكل العام وزر القفل ظاهرين، وواجهة التعافي داخل العرض بلا فائض |
| التعافي بالتنقل | مغادرة الدرس المنهار إلى درس آخر تعيد الرندر الطبيعي دون إعادة تحميل |
| العودة من واجهة التعافي | «العودة إلى صفحة الدروس» تعيد الفهرس ببطاقاته الـ 62 |

### كيف يُحدث الانهيار دون كود حقن في الإنتاج؟

يُعاد استخدام حزمة الاختبار الموجودة أصلًا من **Fix #2**:
`scripts/fixtures/error-boundary/harness/`. تبني `App` الحقيقي بكامله مع
استبدال مكوّن الدرس 2 **وقت البناء فقط** بمكوّن يرمي خطأ. لم تُضف أي آلية حقن
جديدة، ولا يوجد أي كود حقن في حزمة الإنتاج. أخطاء الحقن تُصنَّف **منفصلة**
في التقرير عن أي خطأ غير متوقع.

## 3. التشغيل

```bash
npm run build                          # إلزامي: التدقيق يقرأ dist/
npm run audit:runtime-all-lessons      # كل الدروس + التنقل + الانهيار (~2.5 دقيقة)
npm run audit:runtime-all-lessons:smoke # بوابة سريعة: 3 دروس (تُستخدم في CI)
```

خيارات:

```bash
node scripts/audit-runtime-all-lessons.mjs --lessons=1-10   # نطاق محدد
node scripts/audit-runtime-all-lessons.mjs --skip-nav       # الدروس فقط بلا تنقل/انهيار
```

### المخرجات

| الملف | المحتوى |
| --- | --- |
| `docs/runtime-audit/report.json` | تقرير آلي كامل: كل سناريو، كل فحص، كل تشخيص، التصنيف |
| `docs/runtime-audit/summary.md` | ملخص بشري مقروء |
| `docs/runtime-audit/screenshots/` | لقطة **لكل إخفاق فقط** (لا تُنشأ عند النجاح) |

كل إخفاق يُسجَّل معه: رقم الدرس، المسار، المقاس، الفحص الفاشل، أخطاء
console، أخطاء الصفحة، الطلبات الفاشلة، مسار اللقطة، وهل الفشل **قابل
للتكرار** (تحدده إعادة تشغيل معزولة مرة واحدة على صفحة جديدة).

## 4. تصنيف الإخفاقات

التصنيفات تبقى منفصلة ولا يُعاد تصنيف أي إخفاق لإرضاء نتيجة ناجحة:

| التصنيف | المعنى |
| --- | --- |
| `new` | إخفاق تطبيقي جديد يكتشفه هذا التدقيق |
| `preexisting` | إخفاق قائم قبل هذا العمل (مُدرج في `KNOWN_PREEXISTING` داخل السكربت) |
| `environment` | خطوط Google الخارجية غير متاحة في بيئة التشغيل — لا تُحسب إخفاقًا تطبيقيًا، لكنها تُسجَّل صراحة |
| `infrastructure` | فشل بنية التدقيق نفسه (تعذّر إعادة التشغيل المعزولة) |

## 5. العلاقة بالتدقيقات القائمة (لا ازدواج ولا تعارض)

هذا التدقيق **لا يستبدل** أي تدقيق قائم ولا يضعف أي فحص، ويترك لكل تدقيق
مسؤوليته:

| التدقيق القائم | ما يبقى مسؤولًا عنه | ما لا يعيده هذا التدقيق |
| --- | --- | --- |
| `audit:layout-width-browser` | ميزانيات العرض عبر 7 مقاسات (1920/1280/1024/768/390…) والشرائح الداخلية ومناطق الاختبار | لا يقيس عرضًا مستهدفًا لكل مقاس؛ يكتفي بغياب الفائض |
| `check:english-direction` / `audit:english-direction` | قواعد عزل الإنجليزية وترتيب الكلمات وBIDI | لا يكرر قواعد النص الدقيقة؛ يتحقق فقط أن العوازل LTR فعليًا في المتصفح |
| تدقيقات الدروس الفردية (`audit:lessonNN`) | صحة المحتوى والتصميم لكل درس | لا يتحقق من صحة المحتوى التعليمي |
| `audit:navigation-lock*` | هندسة «التالي» مقابل «قفل الموقع» ومناطق التبويبات | يتحقق فقط من الحضور/الظهور/الوصول، لا هندسة البكسل |
| `audit:error-boundary-browser` | تفاصيل واجهة التعافي وإعادة المحاولة والأزرار | يعيد استخدام حزمته لكن يفحص احتواء الانهيار داخل المسار الشامل |

المقاسان المطلوبان (1440×900 و375×812) هما الحد الأدنى المفروض في Fix #3.
لا تُضاف مقاسات أخرى هنا لأن الاتساع الكامل مُغطّى في `audit:layout-width-browser`،
وتكراره يبطئ بلا تغطية جديدة.

## 6. التكامل الدائم و CI

- أمر دائم: `npm run audit:runtime-all-lessons`.
- **وظيفة CI مستقلة** `runtime-audit` في `.github/workflows/verify.yml`:
  - لماذا مستقلة؟ مدتها ~2.5 دقيقة مقابل ثوانٍ لبقية الخطوات، وفصلها يحفظ
    سرعة وظيفة `verify` الأساسية.
  - ماذا تشغّل؟ `npm run build` ثم `npm run audit:runtime-all-lessons`، وترفع
    التقرير والملخص واللقطات كأثر (artifact) لمدة 30 يومًا.
  - `continue-on-error: true` لتجنب إسقاط الدمج بسبب تعطّل بيئة المتصفح في
    الـ runner، لكن **نتيجة الفحص وفشله يظهران صراحةً** في سجل الوظيفة وفي
    التقرير المرفوع. لا يُخفى فشل ولا يُصنَّف نجاحًا.
- **بوابة سريعة** داخل وظيفة `verify` الأساسية: 3 دروس على المقاسين
  (`npm run audit:runtime-all-lessons:smoke`) لكشف انحدار «صفحة بيضاء» مبكرًا.
- لم تُحذف أو تُضعَّف أي خطوة قائمة في `verify`: كل الخطوات السابقة باقية
  كما هي، ولم تُعدّل أي baseline.

## 7. الثبات والتكرار

- `reducedMotion: "reduce"` لتحييد حركات الدخول (CSS) وتثبيت الهندسة.
- لا لقطة عند النجاح (حجم المستودع)، ولقطة واحدة فقط لكل سناريو فاشل.
- تُفرَّغ `screenshots/` في بداية كل تشغيل، فلا تبقى أدلة قديمة تُوهم بفشل غير قائم.
- انتظار الرندر شرطٌ صريح (`<main>` بنص غير فارغ) لا زمن ثابت عشوائي.
- أي إخفاق يُعاد تشغيله مرة واحدة على صفحة جديدة ويُسجَّل `reproducible`.
- النتائج لا تعتمد على ترتيب تشغيل الدروس (كل درس يُحمَّل عبر `goto` كامل).

## 8. القيود المعروفة

1. **الشبكة الخارجية:** خطوط Google (`fonts.googleapis.com`) غير متاحة في
   بيئة التشغيل؛ تُصنَّف `environment` ولا تُحسب إخفاقًا. هذا قيد بيئي لا قيد تطبيق.
2. **الخطوات التي تحتاج تفاعلًا:** بعض الدروس (مثل 42 و43) تحتوي خطوات
   اختبار/مختبر لا تتيح التقدم بزر «التالي» قبل إجابة. لذلك روابط
   «الدرس التالي/السابق» تُفحص على الدروس التي تعرضها فعلًا في نهاية مسارها
   (1، 52–56، 58–62)، وهذا مُسجَّل صراحةً في قائمة السناريوهات في التقرير
   بدل الادعاء بتغطية غير قائمة.
3. المقاسان المفحوصان هما المطلوبان في Fix #3؛ بقية المقاسات في
   `audit:layout-width-browser`.
4. التدقيق يفحص الخطوة الأولى من كل درس (مدخل الدرس)، والشرائح الداخلية
   التفاعلية تبقى مسؤولية تدقيقات العرض والدرس الفردية.
